# P5 Packaging and upload

- `paper/submit/` holds the final files after cleaning with pikepdf (Info dictionary and XMP removed; re-scan shows zero leaks).
- **Supplementary material is two separate files:** an appendix PDF and `<codename>-code.zip`. The zip has one top-level directory `<codename>-code/` and a root README covering layout, how paths were anonymized, and what was omitted. Code goes into the supplementary upload, not to an anonymous external repository link. Check sizes against the portal limits (often around 10 MB for PDF and 25 MB for zip).
- Collect upload files in one directory the user chooses, with a list of file, upload slot, and deadline, so they are not confused with figure sources.
- **Before packaging, check whether upload files already exist.** Look in the user's submission staging location, in any notes kept about this paper, and in the repository's `submission/` directory. If they exist, verify instead of rebuilding: compare hashes with the repository build, check whether new results should be included, unpack and scan for leaks. Rebuild only if verification fails. Move old files to a clearly labeled non-upload archive; delete nothing without authorization. Two competing packages near a deadline is the failure this prevents.
- After copying, compare hashes between `submit/` and the upload directory. Convert every deadline to the user's local time zone and show the arithmetic. Leave the last hour for iteration; a figure can be swapped in late, but any layout change must be re-verified on the spot.
- At each milestone: commit, and update the one place where paper progress is tracked. If the tracker has counts (papers, rows per section), recompute them with a script instead of counting by hand. Hand-kept dates such as "today" and deadline stacks do not update themselves; reorder them and remove finished or expired items every time the tracker is edited.
- **Declarations are linked, not independent fields.** If there is no funding, the funding statement uses the publisher's standard no-funding sentence, the CRediT list drops "Funding acquisition", and the submission system's funding field says no funding. Inconsistency gets the paper sent back. Check corresponding-author details against the author information sheet item by item (single or joint corresponding authors, dual-affiliation superscripts, emails). An extra email in a footnote can be read as a second corresponding author. Author sheets containing account passwords never go into deliverables, zips, or notes.
